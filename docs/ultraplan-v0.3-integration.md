## 0. Verdict in one paragraph

Build the whole brief inside titan-harness as gap-fill (Grok verdict B): a native Archon-subset YAML DAG engine that schedules nodes as titan `pi --mode json -p` children; a DB-free hash-chained JSONL run store that every surface reads; a titan-native watchdog that owns compaction, review gates and stalemates; harness levels 0–3 as shape files in a backward-compatible schema v2 cycled by `/titan-level`, `alt+l` and (after an opt-in rebind) `shift+tab`; a `/workflow-monitor` that is an unfocused in-process overlay plus a totals row in the model bar, with `orca terminal split` as an opt-in twin; verification tiers as data with observed-only hard evidence, review-before-report, an n-of-3 ladder and re-authoring at a higher level; `/ultraplan`, `/create-workflow`, `/terraform`, `/local-dev-verify`, `/cloud-simulated-users` as titan commands plus skills; InfraNodus as a package-local MCP catalog entry. Two facts override parts of the brief: Gemini 3.8 Flash and Cerebras Qwen cannot run at xhigh (reported as requested xhigh / effective high everywhere), and Fable 5.1 is not callable from Pi on this machine today (no Anthropic or OpenRouter credential in Pi), so every Fable slot ships with a declared fallback until the operator adds one.

## 1. Architecture decision summary

1. **D1 Engine: native YAML DAG inside titan, not compile-to-dynamic-workflows.** Archon is a documented spec with no engine here; pi-dynamic-workflows 3.10.1 is sandboxed JavaScript with no YAML, no `/create-workflow`, no manager hook, and a fragile local dist patch. Titan children are observable subprocesses that already load host providers, pi-exa and pi-mcp-adapter, which is the only substrate that yields observed provenance, ledgered cost and compaction control. pi-dynamic-workflows stays pinned at 3.10.1 with one **maintained local patch** (the 16-line `/workflows` menu hook in `dist/workflow-commands.js`, kept as a documented patch with `.orig` restore, re-applied by `scripts/apply-dw-patch.mjs` and verified by the boot pin check) and read-only polling of its run JSON; the patch is retired the day upstream accepts a `Symbol.for("pi-dynamic-workflows:manager")` or menu hook, which is the only planned change to that package; no TypeScript port and no YAML in its space; `/workflow export --dw` is a late, optional compile target that emits a JavaScript envelope. (All seats.)
2. **D2 Store: append-only JSONL with a canonical-JSON SHA-256 chain, no database.** K-Dense pattern; zero native dependencies, crash-safe appends, greppable, evidence packages are file copies, tamper-evident. SQLite only as an optional derived index behind a flag; embedded NoSQL rejected. The brief's "NoSQL" is satisfied as document-per-line with hashes. (All seats; explicit disagreement with the brief's wording.)
3. **D3 Watchdog: titan-native `modules/watchdog.ts` at run level.** pi-subagents 0.67's watchdog exports no API, ignores `session_before_compact`, cannot see titan children and does not ledger its spend. Titan handles `session_before_compact` / `session_compact` on the host, pre-empts children at 75 % of their context window, spawns ephemeral read-only inspectors through the existing `audit.ts` spawn path, ledgers their spend, and ingests `subagent_watchdog_warning` cards from any child that still runs pi-subagents. "Clearing the inspected agent's logs" is implemented as **logical clearing**: a fresh checkpoint session plus a `logical_cleared` flag; bytes are never deleted because the hash chain must stay intact. (Seat C architecture + Seat D logical clearing, judge pick.)
4. **D4 Monitor: in-process first.** `/workflow-monitor` opens an unfocused right-anchored overlay (`ctx.ui.custom({overlay:true, …})` + `handle.unfocus({target: editor})`), the belowEditor model bar always carries a totals row, and `/workflow-monitor --split` runs `scripts/titan-monitor.mjs` (a store tailer) in an `orca terminal split` pane or `tmux split-window`. Pi has no sidebar, split or pane API, so the literal "side terminal" is the opt-in path. (Seats A, D; judge pick.)
5. **D5 Hotkeys: `shift+tab` is opt-in; `/titan-level` and `alt+l` are guaranteed.** Pi reserves `shift+tab` for `app.thinking.cycle` and silently drops extension bindings. `/titan-level --claim-shift-tab` writes `{"app.thinking.cycle": "alt+t"}` into `~/.pi/agent/keybindings.json` after a confirm dialog and tells the user to `/reload`; titan registers `shift+tab` at `session_start` only when that file frees it. (All seats.)
6. **D6 Levels are shape files in shape schema v2** (`version: 2`, roles, fan-out pools, callsign pools, `fallback:`, `optional:`, `counted:`), loaded by the existing `model-stack.ts` machinery with v1 bare lists still accepted. Level switches reuse `cycleShape`, `announce()` and `Symbol.for("titan-harness:shape-changed")`. (Seat C.)
7. **D7 Thinking is stored and displayed as `{requested, effective, reason}`** via `modules/thinking.ts` built from Pi's provider data: `xhigh↘high` for `antigravity/gemini-3.8-flash` and `cerebras/qwen-3.8-27b`; high-tier thinking passes through where the provider supports it (xhigh for `xai/grok-4.6`, `openai-codex/gpt-6-astra` and Anthropic Fable; `max` for `openrouter/meta/muse-spark-1.3`, which the brief asks for at max) when credentials exist. (All seats.)
8. **D8 Fan-out numbers are pool sizes, not simultaneous children.** `maxConcurrentChildren` (default 8, ≤ 16) is a semaphore in `child-runner.ts`; `/stack` and `/titan-level` remain the single writer of the three mirrored files (`titan-harness.json`, pi-subagents `globalConcurrencyLimit`, dynamic-workflows `defaultConcurrency`). Watchdogs are capacity, spawned on triggers, never counted in the user-facing fan-out. (Seats C, D, A.)
9. **D9 Evidence is observed, never declared.** Titan hashes bytes after `tool_execution_end` events from child streams and on ingest of runner artifacts (Kane `.evidence`, Momentic `.momentic-mcp/`, Cursor `artifacts/download`, Orca screenshots). A model sentence "tests passed" without a hashed log is a watchdog blocker. (Seat A schema, all seats.)
10. **D10 Verification tiers are data (`modules/workflow/tiers.ts`)** naming required evidence kinds, verifier runners, loop policy and the elevation target level, which is what ties fan-out levels to verification depth (InfraNodus gap 2).
11. **D11 Two loops, both ending in `/create-workflow`.** (a) Audit findings (spec, design, evidence or rule mismatches found by the separate auditor) always go to the architect, who authors a repair workflow (`on_fail: {action: reauthor}` on audit nodes); the builder never negotiates with the auditor. (b) Mechanical CI/test red loops inside the builder at most 3 times with the ladder (fail 1 bumps thinking; fail 2 moves the builder to max reasoning on the max model of its family); this is one counter: `loop.max_iterations` is the mechanical budget and `on_fail: {action: elevate}` fires only after that budget is exhausted, never as a second counter. The third mechanical failure, or the third failed audit cycle for the same feature, freezes the run (`parent_run_id`) and calls `/create-workflow --elevate` at `min(level+1, 3)` with halved `context_budget`, a deeper stack and split phases. Delivery order: the counter, the freeze and the escalation report ship in P4; `/create-workflow --from-findings` and `--elevate` ship in P7; between P4 and P7 both hand-offs are a `cancel` node whose reason carries the escalation report path, so P4's exit is executable without P7. This is the literal brief: "loop back to architect with findings which restart the cycle with a new full workflow" plus "loop on CI / test fail n of 3 before elevating".
12. **D12 Structured output is phased.** v1: JSON Schema appended to the prompt, validate, re-ask ≤ 3 (Archon's own Pi behaviour). v2: a child-side terminating `submit_result` tool that the titan extension registers only when `TITAN_HARNESS_CHILD=1` and `TITAN_NODE_SCHEMA` are both set, a deliberately narrow child mode that registers nothing else, so the recursion guard stays intact. (Seat C; Seat D's full bypass rejected by the judge.)
13. **D13 Archon vocabulary is kept** (`nodes`, `depends_on`, `when`, `trigger_rule`, `context: fresh`, `output_format`, `allowed_tools`, `approval`, `loop`, `$ARTIFACTS_DIR`) so workflows stay readable by a future Archon Pi adapter; titan additions live under `titan:` and per-node role fields.
14. **D14 InfraNodus enters through the manifest key** `"pi": {"mcp": "./mcp/mcp.json"}` (pi-mcp-adapter 2.33.0 package-local MCP, namespaced `titan_harness__infranodus`) and through workflow nodes that call its tools. No native graph code. The same key finally makes titan's existing 10-server catalog auto-load.
15. **D15 Degrade, never crash, on missing credentials.** Codex OAuth is invalid, Pi has no Anthropic or OpenRouter provider configured, and there is no InfraNodus key in Pi's environment. Every slot that cannot authenticate is skipped with a notify and, where declared, replaced by its `fallback:`; the model bar and ledger show the substitution. The two rosters below (target vs runnable today) are both first-class.

## 3. YAML workflow schema (Archon-compatible subset for Pi)

Location `.titan/workflows/<name>/<name>.yaml` (+ `commands/*.md`, `scripts/*`), global `~/.pi/titan-harness/workflows/`. Schema published as `extensions/titan-harness/schema/workflow.v1.json` (generated from `modules/workflow/schema.ts`).

**3.1 Top level.** `apiVersion: titan.harness/v1` · `name` (= directory) · `description` · `version: 1` · `inputs {key: {required?, default?}}` · `returns <nodeId>` · `phases [{title, detail?}]` · `provider: pi` (only value) · `model` · `thinking` · `trigger {cron|every|event, entity_profile?}` (level-2 jobs) · `titan {level, shape, tier, modes [spec|design|test], evidence {require[], dir}, elevation: default|ladder, watchdog {enabled, model?, thinking?, cadence_tools?, stalemate_repeats: 3, on_compaction: halt-inspect|summary-only|off, inspector_timeout_ms: 20000}, budget {usd?, tokens?, max_concurrent_children: 8, context_budget?}, personas []}`.

**3.2 Node types (exactly one per node).** Archon: `command` (`.titan/commands/<name>.md`, `$ARGUMENTS`), `prompt`, `bash` (stdout → `$id.output`, shell-quoted substitutions), `script` (`runtime: bun|uv`; named or inline), `loop {prompt, until|until_bash, max_iterations ≤ 10, fresh_context, interactive, gate_message}`, `approval {message, capture_response, on_reject {prompt, max_attempts 1–10}, preset_key?}`, `cancel`. Titan: `verify {runner: kane|testmu|momentic|cursor-cloud|orca-browser|bash, objective, devices[], headless, …}`, `best_of {n, judge, criteria}`, `interleave {segments, by, synthesize, reauthor}`, `hypothesis {hypotheses[], decide_by}`, `mcp_tool {server, tool, args}`, `workflow {name, fan_out?, isolation: worktree?}`, `remote_agent` is an alias of `verify` with `runner: cursor-cloud`.

**3.3 Fields.** Base (Archon): `id`, `depends_on[]`, `when` (only over nodes with `output_format`), `trigger_rule all_success|one_success|none_failed_min_one_success|all_done`, `idle_timeout`, `timeout` (bash/script), `retry {max_attempts, delay_ms}` (error on loop). AI: `model provider/id`, `thinking`, `context fresh|shared|{resume: id}`, `output_format` (JSON Schema), `allowed_tools`/`denied_tools`, `system_prompt`, `append_system_prompt`, `systemPromptMode`, `hooks`, `mcp []`, `skills []`, `subagents {enabled, tools, cap}`, `phase`, `output_type`, `maxBudgetUsd`. Titan per-node: `role architect|builder|worker|verifier|auditor|watchdog|fusion|judge|fuser` (resolves model/thinking/callsign from the shape when `model` is absent), `callsign pool|<name>`, `persona`, `mimeograph`, `tier` (override), `evidence {produces[], require[]}`, `review required|optional|none` (default `required` for builder nodes), `on_fail {action: retry|elevate|cancel, max: 3}`, `watchdog {policy: inherit|off|strict}`, `budget`, `context_budget` (tokens; the authoring architect splits nodes that exceed it), `isolation none|worktree`, `anonymize`.

**3.4 Validator rules (`validator.ts`, load time).** Archon set: unique ids matching `^[a-z0-9][a-z0-9-_]{0,31}$`; `depends_on` resolvable; acyclic (Kahn); `$id.output` refs known and `when:` only on nodes with `output_format`; exactly one type key; `script.runtime bun|uv` with matching extension and named scripts present; `retry` on loop = error; `approval.message` and `cancel` reason non-empty; `on_reject.max_attempts` 1–10; `steps:` rejected. Titan additions: `name` equals directory; `provider` absent or `pi`; `phase` titles exist in `phases`; **`role: architect` nodes may only be `prompt`, `command` or `approval` nodes with read-only tools (`read`, `grep`, `find`, `ls`, read-only MCP tools); the validator injects `denied_tools` for `write`, `edit` and write-capable `bash`, and rejects `bash`, `script`, `workflow`, `verify`, `loop` and write-capable `mcp_tool` under that role so constraint 5 cannot be bypassed by node type**; every builder node with `review: required` must reach an `auditor` or `verify` node before `returns`; the tier's required evidence kinds must be `produces`d by some node (static check); `verify` nodes need `runner` and non-empty `evidence.require`; `best_of.n` 2–8; `interleave.segments` 2–16; `hypothesis` ≥ 1 hypothesis + `decide_by`; callsigns unique per run; `model` matches `/^[^/\s]+\/[^\s]+$/` and resolves in Pi's registry (warn if unauthed, error if unknown); thinking above the model's ceiling → warning `requested xhigh / effective high` and the effective value is stored; `hooks` responses static only; `context: shared` forbidden after a parallel layer; `loop.max_iterations` ≤ 10; `trigger` cron parses; `budget.max_concurrent_children` ≤ 16; tier `platform-update` ship nodes require a `verify` sim-user ancestor.

```yaml
apiVersion: titan.harness/v1
name: proto-analytics-dashboard
description: Prototype a sales-analytics page; spec + TDD; Cursor cloud + Kane verification; separate auditor
version: 1
returns: report
phases: [{title: plan}, {title: build}, {title: verify}, {title: audit}, {title: report}]
inputs:
  spec:   { required: true }                 # path to spec.md
  design: { default: design/dashboard.png }  # design-matching reference
titan:
  level: 3
  shape: level-3
  tier: prototype-analytics
  modes: [spec, design, test]
  elevation: default                         # 1 bump thinking · 2 max model · 3 re-author at level+1
  watchdog: { enabled: true, stalemate_repeats: 3, on_compaction: halt-inspect }
  budget: { usd: 25, max_concurrent_children: 8, context_budget: 120000 }
nodes:
  - id: spec-map
    role: architect
    phase: plan
    context: fresh
    prompt: "Read $spec and produce a feature/acceptance matrix with test ids per device (desktop, mobile)."
    allowed_tools: [read, grep, find, ls]
    output_format:
      type: object
      properties: { features: { type: array }, tests: { type: array } }
      required: [features, tests]
  - id: test-suite
    role: builder
    callsign: pool
    phase: build
    depends_on: [spec-map]
    context: fresh
    prompt: "Author the failing test suite for $spec-map.output.tests, one suite per end device. Do not implement features."
    evidence: { produces: [test-log] }
  - id: implement
    role: builder
    phase: build
    depends_on: [test-suite]
    review: required
    loop:
      prompt: "Implement the next failing feature from $spec-map.output.features and run the suite. When green: <promise>COMPLETE</promise>"
      until: COMPLETE
      until_bash: "bun test"
      max_iterations: 3                      # CI/test red loops here at most 3 times
      fresh_context: true
    on_fail: { action: elevate, max: 3 }     # 1 thinking bump · 2 max model · 3 freeze + /create-workflow --elevate
  - id: cursor-verify
    phase: verify
    depends_on: [implement]
    verify: { runner: cursor-cloud, repo: ".", ref: "$implement.output.branch", objective: "Run the suite and exercise the dashboard; capture screenshots" }
    evidence: { require: [test-log, screenshot] }
  - id: kane-flows
    phase: verify
    depends_on: [implement]
    verify: { runner: kane, objective: "As a sales manager, filter by region and export CSV", devices: [desktop, mobile], headless: true }
    evidence: { require: [screenshot, console-log, evidence-pack] }
  - id: audit
    role: auditor                            # ephemeral, cross-family, read-only, fresh session per round
    phase: audit
    depends_on: [cursor-verify, kane-flows]
    trigger_rule: all_done
    context: fresh
    prompt: "Audit $ARTIFACTS_DIR/evidence against $spec, the design $design, performance budgets and org rules. Verdict YAML."
    output_format: { $ref: "titan://schemas/audit-verdict" }
    on_fail: { action: reauthor }            # every failed audit: findings harvested to the architect → repair workflow via /create-workflow
  - id: report
    role: architect
    phase: report
    depends_on: [audit]
    when: "$audit.output.status == 'PASS'"
    prompt: "Write the acceptance report from $ARTIFACTS_DIR/evidence, citing the sha256 of every artifact."
```

**3.6 Archon / K-Dense precedent boundary.** Archon stays spec-only: titan adopts its vocabulary (node types, base fields, `when` grammar, trigger rules, `$ARTIFACTS_DIR` artifact-handoff doctrine, load-time validator rules) and nothing else. Explicitly not built: the Archon engine or CLI, its SQLite database, Archon Studio, Claude SDK hook execution, worktree-per-run as a default (opt-in `isolation: worktree` only), and its web/chat adapters. K-Dense precedents adopted, each mapped to a titan module: canonical-JSON SHA-256 digests and append-only JSONL (`hash-chain.ts`, `run-store.ts`); provenance derived from observation with `observed|inferred|declared` confidence and visible degradations (`provenance.ts`); "state block first, narrative second" on compaction (`watchdog.ts`); watchdog as settings plus a standing `WATCHDOG.md` (`skills/titan-watchdog`, `prompts/SYSTEM_PROMPT_WATCHDOG.md`); harvest of child sessions into the parent store on completion (`run-store.ts`); spend-cap gates before every spawn and fail-closed billing classification (`ledger.ts`); resident-run lock, `catchUp: latest` and skip-on-overlap for triggers (`trigger.ts`); evidence-package shape with `missing-information` and per-artifact identity basis (`evidence.ts`). K-Dense precedents rejected: the flat single-agent topology, unledgered watchdog spend, silent reviewer failure, and hosted-app assumptions. Enforcement: the validator accepts only the documented Archon subset (`provider: pi`, static hooks, warns on Claude-only keys), `tests/precedents.test.ts` asserts that no titan module imports code from Archon or K-Dense (pattern reuse only), and `docs/precedents.md` lists every adopted rule with its source file and line.

## 5. Verification, evidence and the elevation ladder

**5.1 Evidence schema (`evidence/<nodeId>/evidence.json`).** `{schemaVersion: 1, runId, nodeId, agent (callsign), tier, modes[], status: matched|current-unverified|unavailable|excluded, artifacts: [{path, sha256, bytes, kind: screenshot|video|log|test-result|console-log|network-log|evidence-pack|payload|dataset|script|diff|report|db-op-log|approval-receipt, capturedBy: observed|inferred|declared, source: tool|kane|momentic|cursor|orca|testmu|human, ts}], checks: {testsPass, exitCode, logsPresent, screenshotPresent, designMatch?, perfBudgetMet?, orgRulesMet?, userFlowsPassed?}, provenanceSeq[], missingInformation[], reviewedBy?: {callsign, verdictHash}}`. Hard evidence = `capturedBy: observed` only; `declared` never satisfies a requirement; degradations (`unhashed`, `scan-failed`, `truncated`) are explicit rows.

**5.2 Tier requirements (fail closed).**

| Tier | Required hard evidence | Verifier nodes |
|---|---|---|
| web-general | URL list + HTTP status, payload sha256, screenshot; DB-op log with row counts (write → read round trip) | bash/script checks, orca-browser |
| research-planning | plan digest, source ids + digests, alignment table vs `vision.md` / `intent.md` / terraform docs; no execution claims | verifier AI node |
| prototype-analytics | test-runner log + exit code per device, screenshots, script/input hashes, numeric result card, design-match verdict | cursor-cloud, kane, auditor |
| production-swe | above + simulated user-flow video/screenshots + console/network logs, schedule/mission id | kane / momentic / orca-browser, auditor |
| platform-update | diff hash, apply/migration log, coverage report = 100 % of shipped features, post-deploy probe/screenshot, rollback note | all runners + approval |
| content | output hashes, citations with digests, preview screenshot, 3 approval receipts per preset | approval ×3, judge |

**5.3 Review-before-report and the ladder.** No node output reaches the architect or the user summary until a review frame (auditor verdict or verifier evidence) is linked in the store; `done-verified` requires review PASS ∧ required evidence present ∧ a ledger row for the reviewer, otherwise `done-unverified`. Reviewer inputs are `evidence.json`, provenance rows and the scoped `git diff` (existing `audit.ts`, `DIFF_MAX 60000`), never chat claims (InfraNodus gap 3). Control flow (`modules/workflow/elevation.ts`), one model for every tier: **(a) audit loop** — a failed audit verdict is harvested to the architect with the findings package (`artifacts/escalation-report.md`: verdict, evidence ids, diff hash); the architect authors a repair workflow through `/create-workflow --from-findings` (host-persisted, §Appendix B.5; P7 — in P4 the hand-off is a `cancel` node carrying the report path) and the run enters `repairing-workflow` with `parent_run_id`; the builder never resumes on auditor prose; **(b) mechanical loop** — CI/test red (`until_bash`, missing functionality or design-intent proof, "no issue report back") loops inside the builder at most 3 times with the ladder: fail 1 → thinking +1 step (ceiling-aware), same session resumed with the failing log (`USER_PROMPT_AUDIT_CORRECTION.md`); fail 2 → max reasoning on the max model of the builder's family pool in a fresh session; **(c) elevation** — the third mechanical failure, or the third failed audit cycle for the same feature, freezes the run (`status: reauthored`) and calls `/create-workflow --elevate`: architect xhigh, level `min(L+1, 3)`, tier depth +1, `context_budget` halved, nodes split into more and tighter phases, verifiers +1 (InfraNodus gap 2). Content tier loops on human-review rejections. Review-before-report means the architect sees builder output only through review frames, which is why (a) runs through the harvest and not through chat.

**5.5 Watchdog state machine (`modules/watchdog.ts`).** Agent states as in 5.4; watchdog states `idle → armed → inspecting → {cleared | steering | resuming | halted-stalemate | failed}`.

| Trigger | Action |
|---|---|
| Host `session_before_compact` (reason manual or threshold) while a run or plan mode is active | Synchronously build the deterministic state block from the store (run id, phase, node states, evidence ids, open findings, plan digest, last 20 event hashes) in < 1 s; spawn an inspector child over the entries about to be summarized: on `threshold` compactions it runs on the watchdog model (fast) bounded by `inspector_timeout_ms`, default 20 s, honouring the hook's `signal`; on `manual` compactions the operator may raise the bound; the architect-model inspection is reserved for asynchronous child pre-emption below; return `{compaction: {summary: stateBlock + narrative, firstKeptEntryId}}`. Inspector timeout or failure → state block + Pi default narrative + `watchdog-failed` badge; never `{cancel}`. Reason `overflow` or `willRetry` → state block only, no inspector |
| Host `session_compact` | Record `compaction.done` with summary hash; reset the activity tail; `compacting → dispatched-working` |
| Child usage ≥ 75 % of its model context (from JSON `usage.totalTokens`) or a child compaction event in its stream | Halt at the next `tool_execution_end` (SIGTERM group), inspector reviews the transcript tail against the state block; clean → **logical clear**: fresh checkpoint session, prior transcript flagged `logical_cleared`, bytes preserved; loss or hallucination → fresh session on the dispatching architect's model with `USER_PROMPT_RESUME.md` (state block + diff + findings), never a transcript replay (replaying one model's transcript into another tripped a provider classifier) |
| Workflow reached a terminal state without a review frame | Halt, mark `done-unverified`, dispatch an auditor |
| Builder/worker pings the architect (`waiting-architect`) with no review on its last write | Queue the ping with diff + `missing-review` flag; the architect prompt says so |
| Agent stopped (abort, crash, timeout) without review | `done-unverified`; optional last-diff review |
| Review PASS but no report/harvest reached the architect | Force harvest of the child session into the store; re-prompt the architect |
| Identical finding identity (sha256 of category + summary + paths) ≥ `stalemate_repeats` (3) | `stalemate`: end turn, `ctx.ui.confirm` human gate, run paused |
| Reviewer model or auth error | `watchdog-failed`, refuse `done-verified`, notify (never a silent pass) |
| Ledger over `budget.usd` | `held-spend`; no new children until raised |
| `subagent_watchdog_warning` in a child stream (pi-subagents inside a child) | Ingest as a finding (severity mapped), count toward stalemate |
| `input` from the user | Cancel an in-flight inspection (matches pi-subagents) |

Watchdog children use `READONLY_TOOLS`; every inspection is ledgered under `origin: watchdog`; watchdog capacity = `per_fanout` × builders but reviewers are spawned on triggers, not kept resident.

**5.6 Content presets catalog (gap the judge found in all seats).** `.titan/presets/content/<industry>-<content-type>-<user-preference>.yaml`: `{key, industry, content_type, preference_profile (voice, tone, banned_claims, style_guide_ref), rubric: [{criterion, threshold}], reviewers: {human_min: 3, roles: [...]}, receipts_dir}`. **5.7 `/terraform` connectors and automations (gap).** Connectors are declared in `.titan/terraform/connectors.yaml` and implemented as existing surfaces, never new clients: MCP servers already in the catalog (`macro` for org docs, `figma`/`brandfetch` for brand, `testmu` for test data, `infranodus` for graphs), `gh` CLI bash nodes for GitHub issues/PRs, `orca linear` for tickets, read-only `script` nodes with env-named credentials for databases/analytics. **5.9 pi-subagents 0.67.0 watchdog limits and titan compliance policy.** Limits as shipped (pinned 0.67.0): configuration lives only in Pi `settings.json` under `subagents.watchdog` (strict parse; an unknown key disables it); defaults `enabled: false`, `stalemateRepeats: 3`, `agentEndTimeoutMs: 30000`, `cadence.everyNTools ≥ 5`, `severityThreshold: concern`, reviewer input capped at 24,000 characters, `WATCHDOG.md` capped at 8 KB, `lsp` pre-pass caps (3 s, 20 files, 50 diagnostics); child findings reach the parent only as the last 20 warnings in the result envelope; there is no exported API, no `session_before_compact` handling, no cross-session or on-demand review, its spend is not reported, and foreground children (`async: false`) load no ambient extensions. Titan policy: (1) titan owns review for titan children and for runs, and `subagents.watchdog.main.enabled` is left to the operator for plain chat sessions; (2) `subagents.watchdog.children.enabled` stays `false` by default so a titan child never carries a second reviewer, and when an operator enables it titan ingests its cards and ledgers one `source: unmetered` row per review; (3) titan mirrors the proven bounds: stalemate identity ≥ 3, reviewer input ≤ 24,000 characters, cadence ≥ 5 tool calls, review timeout 30 s for cadence reviews and 20 s for compaction inspection, `WATCHDOG.md` ≤ 8 KB; (4) titan never writes `subagents.watchdog.*` keys except through `writeWatchdogModelSettings`-equivalent merges that preserve unknown keys, because a malformed write silently disables the upstream watchdog; (5) `tests/watchdog-limits.test.ts` asserts these numbers against the pinned package's `settings.ts` defaults so a future bump is noticed.

## 6. Data and logging

**6.1 Store decision.**

| Option | Pros | Cons | Verdict |
|---|---|---|---|
| JSONL + canonical SHA-256 chain (K-Dense) | No deps, append-only, crash-safe, greppable, evidence packages are copies, tamper-evident, immune to multi-process locking | Queries need scans/indices | **Chosen** |
| SQLite (Archon `~/.archon/archon.db`) | Queries, 16-table precedent | Native module or Node ≥ 24 `node:sqlite`; Archon has no hash layer | Optional derived index (`store.sqliteIndex`) |
| Embedded NoSQL | Document model | New dependency, weaker tooling, same hashing work, no local precedent | Rejected |

**6.2 Layout.** `~/.pi/titan-harness/runs/<projectSlug>/<runId>/{run.json, events.jsonl, ledger.jsonl, provenance.jsonl, notebook.jsonl, hypotheses.jsonl, agents/<callsign>.json, evidence/<nodeId>/evidence.json, artifacts/nodes/<id>.md (+ .meta.json), blobs/<sha256>}`; project-side committable `.titan/{workflows,plans,terraform,presets,personas}`; `.titan/runs.json` index (last 300 runs, like pi-dynamic-workflows). Single writer = host process; children never write the store. Child sessions remain `/tmp/titan-harness-sessions/<projectSlug>/run-<pid>/<slotId>` and are removed on `session_shutdown`; the store keeps the hashed harvest.

**6.3 Schemas.** `run.json`: `{runId, projectSlug, workflow{name, sha256}, level, tier, shape, status pending|running|paused|reauthored|completed|failed|aborted|stalemate, currentPhase, phases[], startedAt, endedAt, totals, parentRunId?}`. `agents/*.json`: `{agentId, callsign, role, model, thinking{requested, effective}, parent, sessionDir, state, stateHistory[{state, ts, seq}], usage{input, output, cacheRead, cacheWrite, cost}, tps{outputTokens, seconds}}`. `events.jsonl` row: `{seq, ts, runId, agentId?, type, data, prev, hash}` with `hash = sha256(canonicalJson(row − hash))`, `prev` = previous hash, genesis `"0"×64`; `verifyChain()` on open; types `run.*, phase.*, agent.state, tool.start, tool.end, usage, review.verdict, evidence.captured, watchdog.finding, compaction.*, elevation.*`. `ledger.jsonl`: `{ts, runId, agentId, role, model, provider, thinking{requested, effective}, tokens{input, output, cacheRead, cacheWrite}, costUsd, source: observed|estimated|unmetered|external, origin: run|auditor|watchdog|compaction-inspector|verifier|host|cursor}`. `provenance.jsonl`: `{ts, runId, agentId, toolCallId, tool, inputs[], outputs[{path, sha256, size, mtimeMs, change, confidence}]}`.

**6.4 Provenance rules.** `observed` = tool named the path and titan hashed bytes after `tool_execution_end`; `inferred` = bash/subagent scan-diff or harvest mtime window; `declared` = model assertion only (a claim, never evidence; reviewers see the label). Harvested identities → `identityAt: harvest`, staleness `unverified` until rehash; never re-label current bytes as historical; violations degrade visibly.

**6.5 Cost ledger and sidebar totals.** Host turns via the existing `before_provider_request → message_end` clock (`usage.cost.total`; `message_start` is never used); children via JSON `usage` events (existing absorb path, input + cacheRead + cacheWrite as prompt); auditors, watchdogs, inspectors and verifiers as titan children → `origin`-tagged rows; pi-subagents' own watchdog inside children is unmetered → row `source: unmetered, count: 1` and it stays off by default. Budget checks read the ledger before each spawn; field-wise max of event tally vs `getSessionStats` delta so compaction cannot shrink totals. Totals: token burn = Σ `tokens.input + output` over the run's ledger rows; cost = Σ `costUsd` (+ an `unmetered` badge); avg tps per agent = mean over agents of `outputTokens / seconds` (tool time excluded, existing `runTps`); completion rate = `done-verified / (done-verified + done-unverified + failed + cancelled + stalemate)`, shown for the run and rolling over the last 20 runs. Rendered as `Σ 1.24M tok · $3.87 · 41 tps/agent · verified 86 % (12/14)`.
